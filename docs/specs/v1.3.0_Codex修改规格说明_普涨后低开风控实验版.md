## 5. 普涨后低开风控规则

### 5.1 执行时间

在 09:32 附近，对已有持仓执行检查。

如果当前已有 09:32 交易/检查函数，优先接入现有流程。
不要新增高频检查。

---

### 5.2 市场状态条件

触发前提：

```text
昨日市场状态满足：
prev_regime == bull 或 prev_reg2 == bull
且 prev_trend == up
```

市场状态来源：

```text
优先复用当前策略 DIAG / after_market_close 中已经计算出的 regime、reg2、trend。
```

需要在每日收盘时记录：

```python
g.prev_regime
g.prev_reg2
g.prev_trend
```

供下一交易日 09:32 使用。

如果当前代码已经有类似字段，复用已有字段，不要重复计算复杂市场宽度。

如果找不到 `reg2`，可以只使用：

```text
prev_regime == bull
且 prev_trend == up
```

但必须在最终报告中说明。

---

### 5.3 个股低开条件

对每只已有持仓计算：

```text
open_gap = day_open / prev_close - 1
```

触发条件：

```text
open_gap <= -2%
```

---

### 5.4 抱团强势票过滤

为了避免误伤普通低开洗盘，只对已有明显强势利润的持仓触发：

```text
max_floating_pnl >= 10%
```

如果 `max_floating_pnl` 取不到，则使用保守替代：

```text
当前 pnl >= 5%
```

## 6. 触发动作

触发普涨后低开风控后：

### 情况 A：仍有盈利，且仍在 MA5 上方

```text
if pnl > 0 and ma5_distance >= 0:
    卖半仓
    reason = breadth_gap_risk_reduce
```

要求：

```text
必须复用现有 partial sell / submit_partial_stage_change / 实际成交数量确认 / 账本入账流程。
不允许新写一套半仓账本。
```

---

### 情况 B：仍有盈利，但已经跌破 MA5

```text
if pnl > 0 and ma5_distance < 0:
    清仓
    reason = breadth_gap_risk_exit
```

要求：

```text
必须复用现有 submit_exit_order / finalize_exited_position / 账本入账流程。
```

---

### 情况 C：已经不盈利

```text
if pnl <= 0:
    清仓
    reason = breadth_gap_risk_exit_loss
```

要求同上，必须复用原清仓和账本流程。

## 背景

- 是否没有 accounting_error=1
