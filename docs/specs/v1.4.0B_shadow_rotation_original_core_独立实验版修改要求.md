# v1.4.0B Shadow Rotation Original Core 独立实验版修改要求

## 0. 本次目的

v1.4.0A 的真实回测收益明显下降，初步判断不是卫星仓单独亏损导致，而是核心仓参数从原版结构改成 `35% + 35%` 后，核心仓表现被放大拖累。

因此 v1.4.0B 的目标不是继续加功能，而是做一次**控制变量实验**：

```text
恢复原核心仓参数
保留影子轮动卫星仓
降低卫星仓影响
验证“卫星仓本身是否能增厚收益”
```

---

## 1. 硬性要求

本次只创建独立实验版，不修改任何原策略文件。

```text
不要修改 战车A龙头3.py
不要覆盖 v1.4.0A 文件
不要修改研究脚本
不要删除任何文件
不要 git add
不要 git commit
不要绕开账本
不要引入未来函数
不要新造复杂 risk_off 模型
```

新增文件：

```text
战车A龙头3_v1.4.0B_shadow_rotation_original_core.py
WORKLOG_v1.4.0B_shadow_rotation_original_core.md
```

---

## 2. 实验背景

v1.4.0A 真实回测暴露的问题：

```text
收益明显降低
最大回撤扩大
核心仓胜率明显偏低
实际没有长期满仓
卫星仓整体略正贡献，但贡献不足以抵消核心仓变差
```

所以 v1.4.0B 要恢复原核心参数，单独观察卫星仓是否有效。

---

## 3. 版本定位

v1.4.0B 是：

```text
原核心策略 + 小卫星仓影子轮动
```

不是：

```text
满仓复利版
激进仓位版
Full-B 70/15/15 版
Full-C 60/20/20 版
```

本版本优先验证稳定性，不追求最大收益。

---

## 4. 核心仓必须恢复原策略结构

请检查 v1.4.0A 中被改动的核心仓参数，并恢复到原策略结构。

建议恢复为：

```python
top1_pos_ratio = 0.35
top2_pos_ratio = 0.25
max_initial_position_ratio = 0.60
max_total_position_ratio = 0.75
max_total_positions = 3
```

解释：

```text
核心仓最多 2 个
Top1 35%
Top2 25%
核心初始总仓 60%
总仓位上限先恢复到 75%
预留 15% 给卫星仓
```

注意：

```text
不要再使用 v1.4.0A 的 core 70% 结构
不要再使用 Top1 35% + Top2 35%
不要修改原核心选股、买入、卖出、止损、止盈、账本逻辑
```

---

## 5. 卫星仓结构

v1.4.0B 第一阶段只开 1 个卫星仓。

新增或调整参数：

```python
g.shadow_rotation_enabled = True
g.shadow_satellite_slots = 1
g.shadow_satellite_slot_ratio = 0.15
g.max_total_position_ratio = 0.75
```

解释：

```text
核心仓目标 60%
卫星仓最多 1 个，目标 15%
总仓位上限 75%
```

这样可以最大限度控制变量：

```text
只验证卫星仓是否能提升原策略
不额外放大总仓风险
不改变原核心仓风险暴露
```

## 6. WATCH_POOL 逻辑保留，但要收窄

保留 v1.4.0A 的 WATCH_POOL 框架，但只跟踪 deep_water 候选。

候选加入 WATCH_POOL 条件：

```text
signal_entry_type == deep_water
当日未被核心仓买入
当前未持仓
非 ST
非停牌
非退市
非涨停不可买
非黑名单 / 原策略排除池
通过原策略基础风险过滤
```

WATCH_POOL 字段至少保留：

```text
stock
name
signal_date
signal_price
signal_rank
signal_score
signal_source
signal_entry_type
expire_days = 3
watch_reason
```

注意：

```text
signal_price 不能使用未来不可见数据
如果在收盘后记录，必须明确是在收盘后使用
如果在尾盘记录，必须使用当前时点可见价格
```

## 7. 卫星仓确认规则

继续使用：

```text
Rule D + deep_water
```

确认窗口：

```text
signal_date 后 1-3 个交易日
days_after_signal in [1, 2, 3]
```

确认时间：

```text
尾盘 14:40-14:50
不要早盘确认
```

确认条件：

```text
ret_from_signal >= 5%
day_ret >= 5%
1.0 <= volume_ratio_vs_prev <= 2.0
ma5_distance <= 10%
close_to_day_high >= 0.97
signal_entry_type == deep_water
非涨停不可买
非停牌
非 ST
未持仓
未触发原策略暂停买入状态
```

字段计算必须使用当前时点可见数据：

```text
ret_from_signal = 当前价 / signal_price - 1
day_ret = 当前价 / 昨日收盘价 - 1
volume_ratio_vs_prev = 今日截至当前成交量 / 昨日成交量
ma5_distance = 当前价 / MA5 - 1
close_to_day_high = 当前价 / 今日截至当前最高价
```

如果无法安全获取字段：

```text
记录 SHADOW_CONFIRM_SKIP
跳过该股票
不要用未来全日数据硬算
```

## 8. 卫星仓买入规则

如果当前无卫星仓，且确认通过：

```text
买入 15% 卫星仓
不超过总仓位 75%
现金不足则按可用现金下单
不融资
不加杠杆
```

如果已有卫星仓：

```text
v1.4.0B 第一阶段默认不做替换
```

原因：

```text
先验证单卫星仓本身是否有效
不要让替换逻辑干扰实验
```

可以保留 WATCH_POOL 继续观察，但已有卫星仓时：

```text
记录 SHADOW_BUY_SKIP|reason=satellite_slot_full
```

---

## 9. 卫星仓退出规则

卫星仓独立退出，不影响核心仓。

退出条件：

```text
1. 最长持有 5 个交易日，到期退出
2. 卫星仓亏损 <= -6%，止损退出
3. 当前价跌破 MA5 且 pnl <= 0，退出
4. 持有超过 3 日且 pnl <= 0，退出
5. 原策略已有全局清仓逻辑触发时，跟随原策略
```

不要新造复杂退出。

---

## 10. 核心仓与卫星仓隔离

必须给卫星仓单独标记：

```text
slot_type = satellite
strategy_tag = shadow_rotation
entry_rule = rule_D_deep_water
signal_date
confirm_date
entry_price
satellite_slot_ratio = 0.15
max_hold_days = 5
```

核心仓保持原标记或补充：

```text
slot_type = core
strategy_tag = original_core
```

要求：

```text
同一只股票不能既是核心仓又是卫星仓
已有核心仓不买卫星仓
已有卫星仓不重复买
卫星仓卖出必须走现有安全卖出和账本同步流程
不允许绕开 partial sell 实际成交数量修复
不允许新写一套 TRADE_CLOSE 结算逻辑
```
