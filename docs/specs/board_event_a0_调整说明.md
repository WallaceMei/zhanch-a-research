# 打板事件模块 A0 — 执行调整说明（配合主 Spec 使用）

> 本文件是对《打板事件模块 A0 — 设计参数与执行 Spec》的补充调整。
> 主 Spec 的设计参数（C分层+B扩展池 / T+1open起算 / 池内IC / 滚动验证 / 样本阈值 / Gate0+1小闭环 / 自检）全部沿用，只在以下三处做调整。CC 执行时以"主 Spec + 本调整说明"为准，冲突处以本说明为准。

---

## 调整 1：测试因子改用 194 因子里的真实因子，不用主 Spec §8 的示意名

主 Spec §8 列的测试因子（auction_strength / open_gap / sealed_strength 等）是**示意性**的，不是 194 因子里的真实字段。

**改为**：从 `rdagent_factors_v4.jsonl` 那 194 个因子里，挑 **5-10 个最容易在现有数据上算出来的**当 A0 测试因子。挑选标准：
- 优先挑**只依赖 K 线就能算**的（如依赖 retail_line_change / return_3d / rsi_14 / vol_ratio_5d / price_position_60d 这类纯价量字段的因子）
- 避免挑依赖 seal_strength（需 tick 封单）/ lhb_net（需 AKShare 龙虎榜）这类**取数复杂**的因子——这些留到 A1 全量接入时再处理
- 目的是用**真实因子 + 现有易得字段**把链路跑通，避免 A0 用示意因子验通、A1 接真因子时又撞字段坑

报告里列出：A0 实际选了哪 5-10 个 194 因子、各自依赖什么字段、为什么选这几个（容易算）。

---

## 调整 2：A0 先用现有数据跑通链路，不要求一次性补齐全量打板数据

主 Spec 默认数据已就绪，但实际上 seal_strength（tick·L1）/ 龙虎榜（AKShare）/ 散户线（K线）等数据还没拉齐、没拼成面板。

**A0 阶段的数据策略**：
- **优先用现有能直接拿到的数据**跑通链路：
  - K线（miniQMT 日线，2024-2025）→ 算 retail_line_change、价量类因子、涨停判定、事件池、前向收益
  - 现有 qlib_data 那套 2024-2025 数据 / features.parquet / limit_up 的 csv，能用就用
- **不要求 A0 就把 tick 封单、AKShare 龙虎榜全部拉齐**——这些取数工作留到 A1（接入 194 全量因子）时再认真做
- A0 的目的是验证"**事件池定义 + 池内 IC + 滚动验证 + 自检**"这条**方法链路**对不对，用现有数据（哪怕字段不全、哪怕稀疏）跑通即可
- 如果某个选中的测试因子依赖的字段现有数据没有，就换一个能算的因子（回到调整1的挑选原则）

报告里说明：A0 用了哪些现成数据源、哪些字段是现成的、哪些留到 A1 补。

---

## 调整 3：滚动窗口 M=120 和 M=60 两套都跑，报告对照，主口径待定

主 Spec §4 把 M=120 设为主口径、M=60 设为敏感性。但考虑打板因子易失效，半年（M=120）的挖掘窗口可能偏长，近期规律变化快。

**改为**：A0 阶段 **M=120 和 M=60 两套都跑，报告里并列对照**，暂不指定哪个是唯一主口径。
- 输出两套各自的滚动验证结果（每个测试因子在 M=120 和 M=60 下的 valid_mean_ic / valid_hac_t / pass_validation）
- 报告里对照：哪些因子两套都稳、哪些只在 M=60 稳（可能近期过拟合）、哪些只在 M=120 稳
- **主口径选哪个，等看了 A0 的对照数据，由 Wallace 拍**（不在 A0 里写死）

这样既验证了滚动验证机制能跑通，又为"打板因子该用多长挖掘窗口"积累了实证依据。

## 不变的部分（重申）

以下主 Spec 的内容全部不变：
- 样本池：C 分层（首板/连板分开）+ B 扩展池（纳入冲板失败/炸板负样本）+ 各事件标签
- 收益：主 T+3、辅 T+1/T+2/T+5，全部从 T+1 open 起算（防隐性未来函数）
- 池内 Rank IC + Top-Bottom Spread 辅助
- 样本阈值：总池25/首板15/连板10（不足降8标 small_sample_warning）
- 数据周期：2024-2025 开发验证，2026 封存不调参
- A0 只做 Gate0+Gate1，不接 Gate2/3/4，不标 robust_alpha
- 四项自检（事件池/收益对齐/泄漏/打乱目标）全做，打乱目标后 IC 必须归零，自检不过就停下报告
- A0 成功标准 = 链路跑通 + 自检过，不是找到强因子
