## 4. 第二部分：交易账本 V2 修复

### 4.1 当前问题

`v1.1.0-trade-accounting` 只是识别 `accounting_error` 并跳过 `DRAGON_PAUSE`，但没有真正补齐部分卖出金额。

典型问题：

```text
协鑫能科 002015.XSHE：
trade_ret=-69.50%
sell_amount_accum=0
sell_value_accum=0
accounting_error=1

万邦德 002082.XSHE：
trade_ret=-46.54% 或 -50.52%
sell_amount_accum=0
sell_value_accum=0
accounting_error=1
```

### 4.2 submit_partial_stage_change 必须立即记录部分卖出账本

当部分卖出订单成功返回后，如果 order 对象非 None，应立即根据本次下单数量和当前价格快照记录：

```text
sell_amount_accum += amount
sell_value_accum += estimated_sell_value
realized_pnl_accum += estimated_sell_value - 对应成本
partial_sell_records append
```

记录字段至少包含：

```text
time
stock
amount
price
value
source=order_submit_estimated
reason
order_id
unique_key
```

要求：

```text
只是账本估算，不改变真实下单。
不允许因为账本记录失败阻断真实卖出。
如果后续 sync_position_meta_with_real_positions 也观察到持仓减少，必须防止重复累计。
```

### 4.3 防止重复累计

每条 `partial_sell_records` 必须有唯一 key。

优先级：

```text
1. order_id
2. date + stock + amount + reason
```

如果已经存在相同 `unique_key`，不要重复累计。

`sync_position_meta_with_real_positions` 如果发现该部分卖出已经通过 `submit_partial_stage_change` 记录过，不要重复加。

### 4.4 finalize_exited_position 使用累计账本

最终清仓时：

```text
total_sell_value = sell_value_accum + final_sell_value
final_trade_ret = (total_sell_value - total_buy_value) / total_buy_value
```

如果：

```text
sell_amount_accum + final_sell_amount 接近 buy_amount_accum
```

则：

```text
accounting_error=0
```

正常分批卖出不应再出现：

```text
sell_amount_accum=0
sell_value_accum=0
accounting_error=1
```

### 4.5 accounting_error 保守处理

如果仍然 `accounting_error=1`：

```text
输出 TRADE_ACCOUNTING_WARN
输出 TRADE_CLOSE
输出 DRAGON_LOSS_CLASSIFY_SKIP
不增加 dragon_consecutive_losses
不触发 DRAGON_PAUSE
```

## 6. 第四部分：安全性能优化

profile 结果显示主要瓶颈在 `_get_dragon_stock_list_A_impl`。

本版本只允许做等价性能优化。

### 6.1 优化 price_df.groupby('code') 后逐票 sort_values

如果当前逻辑是：

```python
for stock, df in price_df.groupby('code'):
    df = df.sort_values('time')
```

可以尝试改成等价实现：

```python
price_df = price_df.sort_values(['code', 'time'])
for stock, df in price_df.groupby('code', sort=False):
    ...
```

要求：

```text
不改变最终 meta 字段
不改变候选池业务条件
不改变排序规则
不改变 Dragon score
```

### 6.2 优化 valid_range_df dropna 处理

当前 profile 显示类似逻辑耗时较高：

```python
valid_range_df = stock_range_df[['high', 'low', 'close']].dropna()
```

可以做等价优化：

```text
只在必要股票上做
避免重复切片
不改变 max_range / avg_range 计算结果
```

### 6.3 缓存静态股票信息

`get_base_stock_universe` 中 `get_security_info / start_date` 属于静态信息。

可以新增缓存：

```text
g.security_info_cache
g.security_start_date_cache
```

要求：

```text
只缓存 start_date / display_name / name 等静态字段
不缓存 paused / is_st / last_price / high_limit / low_limit / day_open 这种每日变化数据
不改变新股过滤逻辑
```

### 6.4 本版本不允许做的高风险优化

本版本不允许：

```text
在 get_call_auction 前新增强过滤
把每天 get_call_auction 股票数量从 500+ 主动砍到 100/200
删除 auction 逻辑
用 current_data.day_open 替代 get_call_auction
改变 dragon_min_auction_ratio
改变 dragon_min_auction_amount
改变 dragon_score_mode
改变 deep_water 加分或条件
```

这些可以未来单独做：

```text
v1.2.0-auction-prefilter
```
