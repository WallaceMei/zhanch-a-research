# v1.4.0C 核心/卫星角色轮动：聚宽研究环境直接模拟方案

## 0. 背景

当前不再基于历史日志做新方案验证。

原因：

```text
历史日志只能复盘既有策略路径，不能干净验证“如果当时卫星晋级核心、核心降级”的新机制。
新机制会改变资金路径、持仓路径、后续买入机会和卖出机会。
因此必须在聚宽研究环境中，从原始行情和候选生成逻辑重新模拟。
```

本次目标是新建一个**研究环境直接模拟脚本**：

```text
research_role_rotation_direct_sim_v1.py
```

它只用于研究，不下单，不改策略文件。

---

## 1. 核心目标

验证一个新机制：

```text
核心仓 / 卫星仓动态角色轮动
```

机制含义：

```text
1. 核心仓是主仓位，来自原策略核心候选。
2. 卫星仓是观察仓位，来自 deep_water / Rule D 类强势确认。
3. 如果卫星仓质量持续强于最弱核心仓，卫星仓可以晋级核心仓。
4. 如果核心仓质量弱化，核心仓可以降级为卫星仓或退出。
5. 总仓位和单股仓位必须动态平衡，不能为了满仓而买弱信号。
```

研究问题：

```text
1. 动态轮动是否提高收益？
2. 动态轮动是否降低回撤？
3. 动态轮动是否提高资金利用率？
4. 动态轮动是否只靠少数几笔交易贡献？
5. 动态轮动在不同月份、不同市场状态是否稳定？
6. 动态轮动是否存在明显过拟合风险？
```

## 3. 研究方式：不要基于历史交易日志

本脚本不能用旧日志中的 `TRADE_CLOSE` 作为交易输入。

可以参考已有日志字段定义，但不能把旧日志实际买入卖出作为模拟路径。

禁止：

```text
读取 v14B_fix 的真实买入卖出记录后做反事实换仓
用日志里的实际持仓路径作为新策略持仓路径
用未来 3 日 / 5 日收益作为晋级或降级条件
根据结果倒推参数
```

允许：

```text
读取聚宽原始行情
读取交易日历
每日重新生成候选池
每日重新执行买入、卖出、晋级、降级、仓位控制逻辑
每日重新计算净值和持仓
```

## 7. 候选生成逻辑

第一版不要追求完全复刻策略所有复杂细节，但必须做到逻辑一致、无未来函数。

建议生成两类候选：

### 7.1 核心候选 core_candidates

近似原核心逻辑：

```text
1. 从全市场中过滤停牌、ST、退市、新股等不可交易标的。
2. 用近 5 / 10 日成交额、涨幅、接近 20 日高点、波动区间等构造 prefilter。
3. 生成 dragon / bigmeat 核心候选。
4. 保留 deep_water / trend_core 等 entry_type 字段。
5. 按 score 排序。
```

最少字段：

```text
date
stock
name
score
entry_type
rank
open_ratio
close_to_high
auc_ratio 如果研究环境可取，否则留空
market_trend
```

### 7.2 卫星候选 watch_candidates

来自没有买入核心仓的 deep_water 候选：

```text
1. 当日核心候选中未进入核心仓的 deep_water 标的进入 WATCH_POOL。
2. WATCH_POOL 保留 3 个交易日。
3. 后续 1-3 个交易日用当日行情确认是否转为卫星仓。
```

字段：

```text
signal_date
stock
name
signal_price
signal_score
signal_rank
signal_entry_type
expire_date
```

## 9. 市场状态

可以用简单市场状态，不要复杂过拟合。

建议：

```text
bull：指数在 MA20 上方，且近 10 日涨幅为正
neutral：不满足 bull，也不满足 bear
bear：指数在 MA20 下方，且近 10 日涨幅为负
```

指数可以用：

```text
000300.XSHG
000905.XSHG
399001.XSHE
```

第一版可以只用 000905 或 000300，报告中说明。

市场状态只用于：

```text
1. 控制总仓位上限
2. 禁止 bear/panic 状态下激进晋级
```

不要为了收益过度调市场状态阈值。

## 10. 买入逻辑

### 10.1 核心仓买入

每日 09:32 模拟买入。

规则：

```text
1. 如果核心仓未满，从 core_candidates 选择 top1 / top2。
2. Top1 目标仓位 35%。
3. Top2 目标仓位 25%。
4. 不买停牌、ST、涨停不可买标的。
5. 总仓位不得超过当前 cap。
6. 不允许同一只股票同时作为 core 和 satellite。
```

模拟成交价格：

```text
优先使用 09:32 附近分钟价；
如果取不到分钟价，用当日 open 或 close，并在报告中说明。
```

### 10.2 卫星仓买入

每日 14:45 模拟确认。

确认条件第一版不要复杂优化，沿用 v14B_fix 粗规则：

```text
days_after_signal in [1, 2, 3]
ret_from_signal >= 5%
day_ret >= 5%
1.0 <= volume_ratio_vs_prev <= 2.0
ma5_distance <= 10%
close_to_day_high >= 0.97
signal_entry_type == deep_water
非涨停、非停牌、非 ST
当前无 satellite
不与 core 重复
总仓位 cap 有剩余
```

如果剩余仓位不足：

```text
remaining_cap = cap - current_total_position_ratio

如果 remaining_cap <= 0：
    跳过
如果 0 < remaining_cap < 5%：
    跳过，避免小碎单
如果 5% <= remaining_cap < 15%：
    用 remaining_cap 买入
如果 remaining_cap >= 15%：
    用 15% 买入
```

## 11. 卖出逻辑

### 11.1 核心仓退出

第一版用简化但稳定的退出：

```text
1. 止损：pnl <= -6%
2. 跌破 MA5 且 pnl <= 0
3. 持有超过 5 日且 pnl <= 0
4. 从持仓最高收益回撤超过 10%
```

如果能复用原策略已有退出逻辑，可封装成函数，但不要直接改策略文件。

### 11.2 卫星仓退出

```text
1. 持有 5 日到期
2. pnl <= -6%
3. 跌破 MA5 且 pnl <= 0
4. 持有超过 3 日且 pnl <= 0
5. 晋级为核心后，不再作为 satellite 退出
```

## 12. 角色评分 position_quality_score

不要过度复杂。

第一版评分用粗档位：

```text
score = 0

浮盈 pnl_pct:
  pnl >= 10%: +30
  pnl >= 5%: +20
  pnl >= 0%: +5
  pnl < 0%: -10

MA5 状态:
  price >= MA5: +15
  price < MA5: -20

从持仓最高点回撤:
  drawdown_from_high <= 3%: +10
  drawdown_from_high >= 8%: -20
  drawdown_from_high >= 12%: -35

日内强度:
  day_ret >= 5%: +15
  day_ret >= 2%: +8
  day_ret < -3%: -10

接近日内高点:
  close_to_day_high >= 0.97: +10
  close_to_day_high < 0.93: -10

持仓天数:
  hold_days <= 1: 0
  hold_days 2-5: +5
  hold_days > 5 且 pnl <= 0: -15

原始信号分:
  signal_score >= 0.75: +10
  signal_score >= 0.70: +5
```

注意：

```text
这些是粗规则，不允许通过回测结果反复微调。
```

## 13. 卫星晋级核心规则

卫星仓晋级必须满足：

```text
1. satellite 已持有至少 1 个完整交易日。
2. satellite pnl_pct >= 3%。
3. satellite price >= MA5。
4. satellite close_to_day_high >= 0.96。
5. satellite_score >= weakest_core_score + 10。
6. weakest_core 出现弱化条件之一：
   - pnl_pct <= 0
   - price < MA5
   - drawdown_from_high >= 8%
   - hold_days > 3 且 pnl_pct <= 2%
7. 市场状态不是 bear。
8. 当日未发生其他角色轮动。
```

每天最多一次晋级。

日志输出：

```text
ROLE_PROMOTION_CANDIDATE
ROLE_PROMOTION_EXECUTE_SIM
ROLE_PROMOTION_SKIP
```

---

## 14. 核心降级规则

核心仓降级或退出：

```text
1. core_score 明显低于 satellite_score。
2. core 出现弱化条件。
3. 降级后仍满足总仓位 cap。
```

第一版优先使用“退出最弱核心仓，卫星晋级核心”的保守方式。

不要一开始做复杂的“核心降为卫星继续持有”，因为账本和归因更复杂。

即：

```text
weakest_core sell
satellite role changes to core
```

模拟中记录为角色变化，不需要产生真实成交；但如果仓位大小需要调整，则按模拟交易处理。

## 16. 反过拟合检查

必须输出：

```text
1. train / validation / oos 分段表现
2. 月度收益
3. 20 日 / 40 日滚动收益
4. 20 日 / 40 日滚动夏普 proxy
5. 交易样本数
6. 晋级样本数
7. 降级样本数
8. top1 / top3 / top5 盈利贡献
9. 成本敏感性
10. 参数小扰动稳健性
```

### 16.1 参数小扰动

不要优化，只做稳健性测试。

扰动组：

```text
promotion_margin: 8 / 10 / 12
satellite_min_pnl: 2% / 3% / 5%
core_drawdown_weak: 6% / 8% / 10%
satellite_slot_ratio: 10% / 15%
max_total_cap: 75% / 90%
```

要求报告：

```text
如果只有某一组参数明显赚钱，附近参数全部失效，则标记 high overfit risk。
如果附近参数表现都较稳定，则标记 lower overfit risk。
```

### 16.2 贡献集中度

如果：

```text
top3 盈利贡献 > 70%
或晋级交易数 < 10
或卫星交易数 < 20
```

则不能给强结论。

## 19. 最终结论格式

报告最后必须明确：

```text
角色轮动是否优于核心-only：是 / 否 / 不确定
角色轮动是否优于核心+卫星不轮动：是 / 否 / 不确定
角色轮动是否降低回撤：是 / 否 / 不确定
角色轮动是否提高资金利用率：是 / 否 / 不确定
晋级样本是否足够：是 / 否
收益是否高度集中：是 / 否
过拟合风险：低 / 中 / 高
是否建议进入策略观测版：是 / 否
是否建议进入真实执行版：否
```

真实执行版必须为否。

只有当研究版满足以下条件，才允许进入策略观测版：

```text
1. validation 和 oos 都不崩。
2. 不只依赖 top1/top3 大赚。
3. 晋级/降级样本数足够。
4. 成本提高后仍有效。
5. 参数小扰动下不失效。
6. 总仓位 cap 没有异常。
```

## 20. 注意事项

```text
不要追求最高收益。
不要为了某段行情调参数。
不要把样本内最优参数当最终参数。
不要用未来收益作为晋级/降级判断。
不要把日志复盘结果当新机制有效证明。
不要在研究脚本中调用 order_value 等真实下单函数。
```

本研究脚本的目标不是证明策略更强，而是判断：

```text
核心/卫星动态角色轮动是否具有稳定、可解释、低过拟合风险的统计价值。
```
